# QQ 会议简记插件

本插件的目标是为 QQ 会话提供“开会时的简短记录”，而不是做长期归档或回忆留存。适合会后快速整理归档，不承担合规留痕或长期存档职责。

## 设计思路（概要）
- **存储介质**：仅使用内存缓存，不落盘、不上传，避免历史泄露或误用为归档。
- **缓存模型**：按会话（群聊/私聊）维护独立 `deque`，最多保留最近 500 条记录（默认，可通过命令调整），超出自动丢弃最旧消息。
- **线程化分组**：识别 `Reply` 段，按“主消息 + 回复”归类为线程，读取时按锚点顺序展平。
- **写入路径**：收到消息时格式化为 `内容【来源名称】` 后写入对应会话；异步锁保证并发安全；支持会话命令开关缓存。
- **读取路径**：`/record [limit]` 与 `/record_file [limit] [fmt]` 命令直接从内存缓存读取，`limit` 默认 10，最大不超过当前容量上限；`fmt` 支持 `txt`（默认）与 `md`。
- **安全边界**：不做消息持久化；`/record_file` 采用临时文件发送后立即删除，避免长期留存。
- **配置持久化**：通过插件 KV 持久化 `cache_enabled` 与 `cache_limit` 两项配置，重启后自动恢复，不存储消息内容。
- **每日清理**：每日 6 点自动清理 24 小时未活跃的会话缓存键，避免内存膨胀。
- **插件识别**：不再使用 `@register` 装饰器，依赖 AstrBot 自动识别与 `metadata.yaml`。 

## 使用提示
- 可用指令：
	- `/record [limit]`：最近 `limit` 条（默认 10）。
	- `/record_file [limit] [fmt]`：导出最近 `limit` 条为临时文件并发送；`fmt` 可选 `txt|md`。若平台不支持文件或未配置 NapCat 回调地址，发送失败会自动退化为分段文本消息。
	- `/record_thread <anchor_id> [limit]`：按锚点查看该线程的聚焦输出。
	- `/record_threads [limit]`：列出最近的线程摘要（锚点、条数、最后时间、主消息预览）。
	- `/record_cache [on|off|status]`：开启/关闭/查看状态（管理员限定）。
	- `/record_limit [n]`：设置/查询每会话容量上限（管理员限定，范围 1~1000，默认 500）。
- 开会时保持插件运行，结束后通过上述指令快速回顾要点。
- 仅配置项持久化，消息本体不持久化；机器人重启或进程退出后消息记录清空。

## 兼容性提示
- NapCat 回调地址：在 AIOCQHTTP/NapCat 环境下，建议在机器人配置中设置 `callback_api_base` 以启用文件消息上传能力。
- 退化行为：未配置 `callback_api_base`、平台不支持文件消息或文件上传失败时，`/record_file` 将自动退化为“分段文本消息”发送；分段优先按换行/空白切分并尽量避免切断 URL，超长 URL 可能以单段发送；如需较好的排版，可选择 `fmt=md`。

## 可观测性
- 每日清理会在日志中记录清理的会话键示例。
- 线程写入会在调试日志输出新建主消息与追加回复的锚点信息（可用于问题排查）。
